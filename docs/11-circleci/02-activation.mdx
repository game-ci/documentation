# Activation

The orb uses a Unity Editor instance to test and build your projects. Before each job, the orb
activates Unity with your Unity account email, password and serial.

Unity separates its licenses between `Personal` and `Professional`. The former applies to the _free_
and the latter to the _Pro_ and _Plus_ versions. Based on your use case proceed to the
[Personal](#personal-license) or [Professional](#professional-license) license section.

## Personal license

Follow these steps if you are using Unity's _free_ version.

> _**Note:** Do NOT follow the steps for the personal license if you have a professional license._

Personal licenses have no serial key. The orb extracts it from your Unity license file (`.ulf`).

#### Getting the license file

1. Install [Unity Hub](https://unity.com/download) on your machine and log in with the Unity account
   you want to use in CI.
2. Go to `Unity Hub` ⇢ `Preferences` ⇢ `Licenses`, click `Add` and select **Get a free personal
   license**. Even if a license is already listed, click `Add` to make sure the file gets created.
3. Find the `Unity_lic.ulf` file:
   - Windows: `C:\ProgramData\Unity\Unity_lic.ulf`
   - Mac: `/Library/Application Support/Unity/Unity_lic.ulf`
   - Linux: `~/.local/share/unity3d/Unity/Unity_lic.ulf`

   The license isn't tied to an operating system: you can get it on Windows or macOS and use it in
   Ubuntu jobs.

#### Encoding the license

CircleCI environment variables work best on a single line, so encode the file to base64:

```bash
# Linux
base64 -w 0 Unity_lic.ulf
# macOS
base64 -i Unity_lic.ulf
```

#### Configuring your Context

1. Navigate to [CircleCI](https://app.circleci.com/) ⇢ `Organization Settings` ⇢ `Contexts` ⇢
   `Create Context` and choose a name for your context (e.g. `unity`). Alternatively, open an
   existing Context that you would like to use.
2. Create the following environment variables:
   - `UNITY_LICENSE` - _(Paste the encoded license from the previous step)_
   - `UNITY_EMAIL` - _(Add the email address that you use to log in to Unity)_
   - `UNITY_PASSWORD` - _(Add the password that you use to log in to Unity)_

## Professional license

Follow these steps if you are using Unity's _Pro_ or _Plus_ version.

> _**Note:** Do NOT follow the steps for the professional license if you have a personal license._

1. Get your Serial Key from the [subscriptions page](https://id.unity.com/en/subscriptions).
2. Navigate to [CircleCI](https://app.circleci.com/) ⇢ `Organization Settings` ⇢ `Contexts` ⇢
   `Create Context` and choose a name for your context (e.g. `unity`). Alternatively, open an
   existing Context that you would like to use.
3. Create the following environment variables:
   - `UNITY_SERIAL` - _(Paste the serial acquired in **step 1** here. It should look like this:
     `XX-XXXX-XXXX-XXXX-XXXX-XXXX`)_
   - `UNITY_EMAIL` - _(Add the email address that you use to log in to Unity)_
   - `UNITY_PASSWORD` - _(Add the password that you use to log in to Unity)_

**GameCI does not acquire nor store your Unity email, password, serial or license file. They are only
used to activate Unity during your jobs.**

## Upgrading from version 1.x

Version 2 activates Unity the same way as the GitHub Actions. Unity no longer supports manual
activation with `.alf` files, so the old personal license flow stopped working.

- Rename `unity-username-var-name` to `unity-email-var-name`. Its default is now `UNITY_EMAIL`.
- The `unity/create-activation-file` job was removed. Get a license file as described in
  [Personal license](#personal-license).
- `unity-license-var-name` now defaults to `UNITY_LICENSE`. An existing `UNITY_ENCODED_LICENSE`
  variable still works if you pass `unity-license-var-name: 'UNITY_ENCODED_LICENSE'`. Email and
  password are now required for personal licenses too.
- `fetch-submodules` now defaults to `true`, since 1.x always fetched submodules.
- The `unity/macos` executor only accepts the `m4pro.medium` and `m4pro.large` resource classes,
  since CircleCI retired the M1 machines.

## Next steps

Now you are prepared to start [testing](/docs/circleci/test) and [building](/docs/circleci/build)
your Unity project. However, remember to reference your context in every job you run; otherwise,
they will fail:

```yaml
version: 2.1

orbs:
  unity: game-ci/unity@2

workflows:
  build-unity-project:
    jobs:
      - unity/test:
          ...
          context: unity
      - unity/build:
          ...
          context: unity
```
